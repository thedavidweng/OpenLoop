# ADR-0003: Content Security Policy

**Status:** Accepted
**Date:** 2026-05-14
**Author:** OpenLoop engineering

## Context

OpenLoop is a Tauri 2 desktop application that uses a WebView frontend. To prevent injection attacks and limit the attack surface, we need a strict Content Security Policy (CSP).

The challenge is balancing security with Tauri's IPC mechanism, local backend HTTP communication, and Tailwind CSS inline styles.

## Decision

We adopt the following CSP in `tauri.conf.json`:

```json
"csp": "default-src 'self'; img-src 'self' data: blob:; media-src 'self' blob: tauri:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self' ipc: http://ipc.localhost http://127.0.0.1:* http://localhost:*; font-src 'self' data:; object-src 'none'; frame-ancestors 'none'; base-uri 'self'"
```

### Rationale per directive

| Directive                                                                            | Value                                | Reason                                                                                                                    |
| ------------------------------------------------------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `default-src 'self'`                                                                 | Baseline: only same-origin resources | Prevent loading arbitrary external resources                                                                              |
| `img-src 'self' data: blob:`                                                         | Cover images and waveform blobs      | Waveform canvas exports as blob: URLs                                                                                     |
| `media-src 'self' blob: tauri:`                                                      | Audio playback                       | Generated audio served via blob: and tauri: protocols                                                                     |
| `style-src 'self' 'unsafe-inline'`                                                   | Tailwind 4 CSS-in-JS                 | Tailwind 4 requires inline styles; we accept this trade-off because the styles are generated by our build, not user input |
| `script-src 'self'`                                                                  | No inline scripts                    | All JS bundled via Vite; no eval or inline handlers                                                                       |
| `connect-src 'self' ipc: http://ipc.localhost http://127.0.0.1:* http://localhost:*` | Tauri IPC + local backend            | `ipc:` for Tauri commands; localhost for ACE-Step backend HTTP                                                            |
| `font-src 'self' data:`                                                              | Icon fonts                           | Lucide icons and any bundled fonts                                                                                        |
| `object-src 'none'`                                                                  | No plugins                           | No Flash / PDF plugins                                                                                                    |
| `frame-ancestors 'none'`                                                             | No embedding                         | Prevent clickjacking                                                                                                      |
| `base-uri 'self'`                                                                    | No base tag manipulation             | Prevent base-uri hijacking                                                                                                |

### Why `'unsafe-inline'` for style-src

Tailwind CSS v4 uses runtime-generated utility classes that rely on inline `<style>` injection. A nonce-based approach would require:

1. Injecting a nonce from Rust into the WebView
2. Configuring Tailwind to use that nonce

This is possible but adds complexity. Given that:

- All inline styles come from our own bundled Tailwind build
- No user-generated CSS is rendered
- The attack surface is limited to XSS that can inject `<style>` tags

We accept `'unsafe-inline'` as a pragmatic trade-off and will revisit nonce-based CSP when Tauri 2 provides simpler nonce APIs or when we migrate away from Tailwind 4.

### What we do NOT allow

- No external images, fonts, or scripts
- No `connect-src` to arbitrary internet domains (only localhost for backend)
- No `eval()` or `Function()` constructors
- No WebAssembly (not needed for our use case)

## Consequences

### Positive

- Prevents most XSS and injection attacks
- Blocks accidental loading of external resources
- Aligns with Tauri security best practices

### Negative

- `'unsafe-inline'` on style-src slightly weakens XSS protection
- Future features requiring external resources (e.g., cloud model registry) will need CSP updates

## Alternatives Considered

1. **Nonce-based CSP**: Rejected for v0.1 due to Tauri 2 WebView nonce injection complexity. Revisit in v0.3.
2. **No CSP (`null`)**: Rejected — leaves WebView fully exposed.
3. **Hash-based CSP for inline styles**: Rejected — Tailwind generates too many dynamic classes for hash management.
