# Documentation and release workflow

- `CHANGELOG.md` is generated by git-cliff from Conventional Commits. Do not manually edit it; run `pnpm changelog` to regenerate and use clear `feat:`, `fix:`, `refactor:` etc. commit messages.
- Generated documentation must declare its generator and output location in `scripts/README.md`.
- Do not leave completed implementation plans or handoff notes in the repository; track future work in GitHub Issues.
- `pnpm release:check` runs Swift build/tests with warnings treated as errors and validates README/release notes/CLA checks. `pnpm release:build` prepares sidecars, packages the macOS app and runs a CLI smoke test; it is a separate command, not a superset of `release:check`. Use these gates when relevant to release work, not as a requirement for every small edit.
- Existing `docs/agents/issue-tracker.md`, `triage-labels.md`, `domain.md` and `CONTEXT.md` remain authoritative for issue and glossary conventions.
