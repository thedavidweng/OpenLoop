# OpenLoop UI Review -- 改进建议

**定位**: 纯 AI 音乐生成工具。不做社交、不做平台、不做播放器。把和生成相关的每一件事做到极致。

---

## P0 -- v0.1（当前 UI 存在的实际问题）

### Task 1: 生成面板区域比例失调 -- 右列浪费空间

**当前状态**: Stage 区域使用 `grid-cols-[1.35fr_0.65fr]` 两列布局。左列是 GenerationPanel（生成表单），右列是状态信息面板。右列显示：当前生成标题、状态卡、模型信息、文件详情。这些信息密度很低，大量空白。

**问题**: 右列占用了将近三分之一的水平空间，但只承载低密度的只读信息。用户的核心操作（填写表单、点击生成）全部集中在左列。在 1280px 及以下的屏幕上，左列表单空间被压缩，textarea 和参数行变得拥挤。

**做法**:
1. 将右列的信息卡合并到 PlaybackBar 上方或 HistorySidebar 的选中项详情中
2. 让 GenerationPanel 占据 Stage 区域的全部宽度（单列 `grid-cols-1`）
3. 生成状态改为 GenerationPanel 内部的顶部或底部 banner（类似现有的 ModelBootstrapBanner）
4. 模型信息和文件详情移到 Settings 或 HistorySidebar 的展开详情中

**涉及文件**: `src/app/components/layout/OpenLoopStage.tsx`, `src/app/components/player/PlaybackBar.tsx`
**验证**: 在 1280px 宽度下确认 GenerationPanel 的 prompt textarea 和参数行不再被压缩。

### Task 2: Prompt Textarea 和 Generate 按钮并列不合理

**当前状态**: Prompt textarea 和"模型信息 + Generate 按钮"被放在同一行，使用 `grid-cols-[1fr_260px]` 布局。

**问题**: Prompt 是生成过程中最核心的输入，应该获得最大的空间和视觉权重。将它和 Generate 按钮并排放，导致：
- Prompt textarea 被限制在约 116px 高度和剩余宽度内，空间不足
- Generate 按钮被困在右侧列的底部，不够醒目
- 模型状态信息挤在 Generate 按钮上方，视觉层级混乱 -- 模型状态是辅助信息，不应该和核心操作区混在一起

**做法**:
1. Prompt textarea 独占一行，给予更大的高度（`min-h-[140px]`）和全宽
2. Generate 按钮移到表单底部，全宽显示，使用醒目的渐变色或主色调（类似参考实现中 `sticky bottom-0` 的固定底部按钮模式）
3. 模型状态信息移到 Prompt textarea 上方作为紧凑的一行指示器（图标 + 模型名 + 状态徽章），或移到 Settings

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`（区域 B）
**验证**: Prompt textarea 在全宽下舒适可读，Generate 按钮在表单底部全宽醒目显示。

### Task 3: 歌词面板的手动开关交互差

**当前状态**: 歌词面板通过 "添加歌词" / "编辑歌词" 按钮手动开关。按钮在标题行右侧，是一个 `secondary-button`。

**问题**:
- 歌词是生成带人声音乐的必要输入，不应该被隐藏在手动开关后面。新用户可能根本注意到这个按钮，直接提交没有歌词的生成。
- "添加歌词" 按钮的位置（标题行右侧）不够直觉 -- 用户预期歌词输入应该在 prompt 下方直接可见
- 当歌词为空时不显示面板，但有验证错误时又显示 -- 状态切换突兀

**做法**:
1. 歌词 textarea 始终可见，放在 Prompt 下方，不需要手动开关
2. 如果担心界面过长，使用轻量的折叠（默认展开），而不是完全隐藏
3. 歌词区域标题行内放置结构标签辅助按钮（`[Verse]` `[Chorus]` `[Bridge]` 等），这同时也是视觉提示"这里需要填歌词"
4. 歌词为空时不报验证错误，但如果用户没有开启 Instrumental 模式且歌词为空，在歌词 textarea 内显示引导性 placeholder（如 "在此输入歌词...留空将生成纯器乐"）

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`（区域 C）
**验证**: 歌词区域在页面加载时始终可见，结构标签按钮可点击插入。

### Task 4: 高级控制使用原生 `<details>` 标签，体验粗糙

**当前状态**: 高级参数折叠使用原生 HTML `<details>` / `<summary>`。点击时浏览器默认行为，没有动画过渡。

**问题**:
- 原生 `<details>` 展开/收起是瞬间切换，没有任何过渡动画，体验生硬
- 无法通过 JS 精确控制展开/收起状态（例如在表单验证失败时自动展开高级面板显示错误）
- 与应用其他部分的精致 UI 风格不匹配

**做法**:
1. 替换为自定义的 collapsible 组件（用 `max-height` + `overflow:hidden` + `transition` 或 `grid-template-rows: 0fr → 1fr` 技巧实现平滑动画）
2. 添加展开/收起的 chevron 旋转过渡
3. 支持通过 state 控制展开状态，以便在验证失败时自动展开

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`（区域 E）
**代码量**: 约 40-60 行（可抽取为通用 Collapsible 组件）
**验证**: 点击高级控制时平滑展开/收起，chevron 有旋转过渡。

---

### Task 5: 参数行的 select 组件缺少视觉分组和标签层次

**当前状态**: 基础参数行使用 5 列网格放置 Task Type、Duration、BPM、Language、Format 五个字段，每个字段用 `FieldLabel`（11px uppercase）+ `select-input` 或 `text-input`。

**问题**:
- 所有参数平铺在同一行，没有逻辑分组。Task Type 是任务类型（决定整个生成模式），Duration/BPM 是音乐参数，Language 是语言，Format 是输出格式 -- 它们的性质完全不同
- 5 列网格在 `lg` 以下断点退化为单列堆叠，导致表单突然变得非常长
- Task Type（text2music/cover/repaint 等）是一个影响全局的参数，不应该和 Duration 混在同一行

**做法**:
1. 将 Task Type 提取为表单顶部的独立行（或作为模式切换器），放在 Prompt 之前。这决定了用户接下来的输入体验
2. 将 Duration、BPM、Key/Scale、Time Signature 归为"音乐参数"组
3. 将 Language、Format 归为"输出设置"组
4. 每组使用卡片容器和组标题，形成清晰的视觉层次
5. 使用更合理的响应式断点：`md` 时两列，`lg` 时三列

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`（区域 D）
**验证**: Task Type 在表单顶部独立显示，音乐参数和输出设置分组清晰。

## P1 -- v0.2（布局优化和交互提升）

### Task 6: HistorySidebar 的历史条目信息密度不足

**当前状态**: 每个 history item 显示标题（prompt 前几行或 lyrics 前几行）、格式标签（WAV/MP3）、时长标签、状态标签。操作按钮（Use Settings、删除等）使用 `contextual-reveal` 在 hover 时显示。

**问题**:
- 条目没有显示 BPM、调号等关键音乐参数 -- 用户在浏览历史时无法快速判断哪条记录使用了什么参数
- "Use Settings" 操作隐藏在 hover 后 -- 这是最常用的操作之一，不应该需要 hover 才能看到
- 没有缩略图或视觉标识 -- 所有条目看起来一样，纯文字列表缺乏区分度
- 条目之间的视觉区分仅靠边框分割线，不够明显

**做法**:
1. 在每个 history item 中增加一行显示关键参数（BPM、Key、Duration），使用小字灰色
2. "Use Settings" 按钮改为始终可见（使用 icon button 而非文字按钮，节省空间）
3. 添加生成状态的颜色编码左边框（completed 绿色、failed 红色、running 蓝色 pulse）
4. 考虑在条目右侧添加一个微型播放按钮，可以直接在侧边栏快速预览

**涉及文件**: `src/app/components/history/HistorySidebar.tsx`
**代码量**: 约 60-80 行
**验证**: 历史条目显示关键参数，"Use Settings" 按钮始终可见。

### Task 7: PlaybackBar 缺少音量和播放速度控件

**当前状态**: PlaybackBar 有 play/pause、前进/后退 10 秒、进度条、时间显示。没有音量控制，没有播放速度控制。

**问题**: 音量控制是任何音频播放器的基线功能。播放速度对于创作者审查生成结果至关重要。这两个都是纯 DOM API 操作（`audio.volume` 和 `audio.playbackRate`），实现成本极低。

**做法**:
1. 在 PlaybackBar 的进度条和控件区域之间添加音量图标 + 滑块（默认显示图标，hover/点击展开）
2. 在时间显示旁添加速度切换按钮，循环 0.5x / 0.75x / 1x / 1.25x / 1.5x / 2x
3. 音量偏好持久化到 localStorage

**涉及文件**: `src/app/components/player/PlaybackBar.tsx`
**代码量**: 约 50-70 行
**验证**: 拖动音量滑块确认音量变化，切换速度确认播放速度变化，重开 app 确认音量偏好保留。

### Task 8: Generate 按钮缺少状态反馈和进度信息

**当前状态**: Generate 按钮在空闲时显示"生成"，运行时显示"正在生成" + Loader2 旋转。没有进度百分比，没有预估剩余时间。

**问题**: 音乐生成通常需要 30 秒到几分钟。用户只能看到一个旋转动画，不知道进度。这在长时间生成时会造成焦虑。

**做法**:
1. 在 Generate 按钮下方或 PlaybackBar 区域显示生成进度条（如果后端提供进度信息）
2. 按钮文字改为更具体的状态："提交中..." → "生成中... (0:45)" → "下载中..."
3. 如果后端不提供精确进度，使用阶段指示器（queued → running → downloading → completed）而非无限旋转
4. 添加取消按钮（在生成运行时替换 Generate 按钮或显示在旁边）

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`, `src/app/components/player/PlaybackBar.tsx`
**前置条件**: 确认后端 `/query_result` 是否返回进度百分比
**验证**: 提交生成后按钮显示阶段状态，进度条有动态更新。

### Task 9: 缺少 Instrumental Toggle -- 无伴奏模式不直觉

**当前状态**: 没有独立的 Instrumental 开关。用户需要通过清空歌词或修改 prompt 来实现纯器乐生成。

**问题**: "生成背景音乐"是极其常见的使用场景。用户不应该需要理解"清空歌词=无伴奏"这个隐含逻辑。对比参考实现中有明确的 Instrumental toggle，开启后自动隐藏 vocalLanguage 选择器。

**做法**:
1. 在歌词区域标题行添加 "Instrumental" toggle switch
2. 开启时: 歌词 textarea 变灰/禁用，vocalLanguage 选择器隐藏或禁用
3. 关闭时: 恢复歌词输入和语言选择
4. toggle 使用明显的视觉样式（如 active 时显示音符 crossed-out 图标或 "无伴奏" 文字）

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`
**代码量**: 约 40-50 行
**验证**: 开启 Instrumental 确认歌词和语言被禁用，生成结果无伴奏。

---

### Task 10: 表单参数没有合理的默认值策略

**当前状态**: Duration 默认值取决于设备 profile（16GB=180s, 32GB=300s 等），BPM placeholder 显示"可选"，Key/Scale placeholder 显示提示文字。其他参数需要用户手动填写或保持默认。

**问题**: 新用户面对空白的 BPM、Key/Scale、Time Signature 字段会犹豫 -- 不知道填什么。参考实现中这些参数默认为 Auto（值为 0 或 -1），让后端自动推导。

**做法**:
1. BPM 默认值设为 0（Auto），placeholder 显示 "Auto"
2. Key/Scale 默认值设为 "Auto"，作为 select 的第一个选项
3. Time Signature 默认值设为 "4/4"（最常见）
4. Duration 保持当前的设备 profile 默认值策略，但在输入框旁显示 "(推荐: {default}s)" 提示
5. 在每个参数旁添加 tooltip 说明（已有的 Tooltip 组件可复用）

**涉及文件**: `src/app/components/generation/GenerationPanel.tsx`, `src/app/lib/store.ts`（默认值）
**代码量**: 约 20-30 行
**验证**: 新用户打开表单时，所有参数都有合理的默认值，不需要修改即可生成。

### Task 12: 缺少 Toast/通知系统

**当前状态**: 应用使用内联错误显示（FieldError）和状态卡显示错误。没有全局 toast 通知。

**问题**: 生成成功、导出完成、设置保存等操作缺少视觉反馈。用户需要主动查看才知道操作是否成功。

**做法**:
1. 实现一个轻量的 toast 组件，支持 success/error/info 三种类型
2. 在以下场景触发: 生成完成、导出成功、设置保存、复制到剪贴板
3. Toast 从右上角弹出，3 秒后自动消失，支持手动关闭
4. 使用 CSS animation，不需要额外的动画库

**涉及文件**: 新增 `src/app/components/overlay/Toast.tsx`，在 App.tsx 中挂载
**代码量**: 约 80-100 行

### Task 13: 快捷键覆盖不完整

**当前状态**: `app-shortcuts.ts` 存在（1.35 KB），但覆盖范围有限。

**做法**: 确保以下快捷键可用:
- `Space`: 播放/暂停（焦点不在输入框时）
- `Cmd+Enter`: 提交生成
- `Cmd+Shift+R`: 重试上次生成
- `Cmd+N`: 重置表单
- `Cmd+,`: 打开设置

**涉及文件**: `src/app/lib/app-shortcuts.ts`
**代码量**: 约 30-40 行

### Task 14: Settings 面板缺少分组导航

**当前状态**: SettingsOverlay 是一个大型滚动面板，所有设置项平铺。

**做法**: 将设置分组（通用、生成参数、音频、后端、关于），使用左侧导航标签或顶部 tab 切换，避免长滚动。

**涉及文件**: `src/app/components/settings/SettingsOverlay.tsx`
**代码量**: 约 100-150 行
