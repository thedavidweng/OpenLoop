# OpenLoop UI Backlog

**Status**: Active backlog after implementation comparison on 2026-04-29.

The original UI review contained several issues that are now implemented:

- The right-side stage column was removed; `OpenLoopStage` now gives the composer the main workspace.
- Prompt input is full width and the Generate button is a prominent full-width action at the bottom.
- Lyrics are always visible, with structure tag chips and Instrumental mode.
- Advanced controls use the custom `Collapsible` component instead of native `<details>`.
- Basic parameters are grouped and Task Type is independent.
- History items show key parameters, status color, quick play, and always-visible Use Settings.
- Playback has volume and speed controls.
- Settings has section navigation.

This document now tracks only remaining UI work with current product value.

## P1

### Task 1: Generation Progress Detail

Current implementation shows elapsed time, retry, and cancel states. It still lacks finer progress when ACE-Step can expose task phases or percentages.

Expected behavior:
- Show submission, queued, running, downloading, and completed phases distinctly.
- If the backend exposes progress or elapsed backend time, surface it in the composer or status banner.
- Keep current cancel behavior.

Likely files:
- `src/app/components/generation/GenerationPanel.tsx`
- `src/app/lib/store.ts`
- `src-tauri/src/commands/generation.rs`

Verification:
- A running task shows a specific phase instead of only a spinner.
- Downloading generated audio is distinguishable from model inference.

### Task 2: Default Parameter Strategy

Defaults are better than the initial review state, but BPM and key/scale still behave as optional freeform fields rather than explicit Auto choices.

Expected behavior:
- BPM supports an explicit Auto value.
- Key/scale uses a controlled option set with Auto as the first choice.
- Time signature remains `4/4` by default.
- Duration keeps the profile/default setting behavior.

Likely files:
- `src/app/components/generation/GenerationPanel.tsx`
- `src/app/lib/validation.ts`
- `src/app/lib/types.ts`

Verification:
- A fresh form can generate without the user thinking about BPM/key defaults.
- Auto values map cleanly to the ACE-Step request payload.

### Task 4: Toast Provider Wiring

`Toast.tsx` exists, but the provider is not mounted and app actions do not publish toasts yet.

Expected behavior:
- Mount `ToastProvider` near the app root.
- Use it for generation success/failure, export completion, settings save, and file actions.
- Keep inline errors for form and backend details.

Likely files:
- `src/app/App.tsx`
- `src/app/components/overlay/Toast.tsx`
- Call sites in settings/player/generation flows.

Verification:
- Saving settings and copying/exporting audio shows a transient localized toast.

Expected behavior:

Likely files:
